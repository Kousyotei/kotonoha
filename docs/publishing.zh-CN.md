# 手动上传 GitHub

仓库名为 `kotonoha`，公开地址为 [Kousyotei/kotonoha](https://github.com/Kousyotei/kotonoha)。用于面试展示时选择 **Public**，面试官无需登录即可查看。上传源码即可；AI 模型由使用者按 README 在本机另行准备。

## 本次整理的范围

| 公开文件 | 内容 |
| --- | --- |
| `src/`、`server/`、`python/` | 前端、导出服务、本地模型调用代码 |
| `scripts/`、`tests/`、`.github/workflows/ci.yml` | 安装、验证脚本和基础 CI |
| `samples/demo.*` | 原创日文短文与手工编辑的中文示例，不包含录音 |
| `README.md`、`README.zh-CN.md`、`docs/` | 日中文档、架构、评估边界、测试方法、视频输出示例图 |
| `package*.json`、锁文件、项目配置、`start.command` | 可复现的安装和启动配置 |
| `THIRD_PARTY_NOTICES.md` | 辞典、模型及依赖的来源和许可 |

个人录音、私人项目、模型、Python 环境、`node_modules/`、生成的视频、实验记录和 `.private/` 已由 `.gitignore` 排除。它们仍留在原电脑上。原来的文章项目不会被公开示例覆盖，浏览器存档也不会被上传。

`.gitignore` 只影响 Git；直接压缩整个工作文件夹仍会包含私人文件。若使用本次整理提供的公开源码 ZIP，它只包含已提交的公开文件，不含 `.git`、私人素材或依赖。

## 使用 VS Code 上传

1. 用 VS Code 打开项目文件夹，点击左侧「源代码管理」。本地仓库和提交已准备好，无需再次初始化。
2. 之后若继续修改，先查看变更，只暂存准备公开的文件，然后提交。不要使用「强制添加忽略文件」。
3. 按 `⌘⇧P`，运行 `Publish to GitHub`，在 GitHub 官方登录页面完成授权。
4. 若是首次发布，选择自己的账号、仓库名 `kotonoha` 和 **Public**。若仓库已存在且有内容，先核对远程历史，再按正常 Git 流程合并。
5. 本项目已发布后，日常更新在源代码管理中提交并「推送／同步」即可，无需重新发布。打开 GitHub 仓库，核对文件清单、图片、README 和 Actions；页面应显示 **Public**。

使用公开 ZIP 的话，请先解压并打开里面的 `kotonoha` 文件夹，再初始化仓库、提交、发布。不要把 ZIP 本身作为唯一文件上传。

## 发布后的核对

- GitHub 上能看到 `src/`、`server/`、`python/`、`samples/demo.kotonoha.json` 和 `.github/`；看不到私人录音、个人作品、`.models/` 或 `node_modules/`。
- README 的两张图片能显示，中文文档链接能打开。
- Actions 基础检查通过；这不代表已执行真实模型推理或完整浏览器测试。
- 另一份干净目录中执行 `npm ci`、`npm test`、`npm run build`、`npm run dev`，按 README 试用公开示例。

## 面试展示重点

建议先演示“打开示例 → 导入自己的朗读 → 翻译候选和人工修改 → 同步高亮 → 保存并刷新恢复 → 短视频导出”。已知原文的自动对齐需要提前准备模型；首次模型下载不适合放在现场演示中。

技术讲解可围绕句子 ID 映射、旧生成结果保护、人工修正保留、音频事务保存、预览与导出共用排版展开。模型选择与已知局限见 [evaluation.md](evaluation.md)。如实说明 AI 辅助开发过程、自己能够解释和维护的部分，不把现成模型说成自行训练的模型，也不把手工编辑的示例译文当成模型效果。

当前仓库未选择应用源码的开源许可证。公开展示与授予开源使用许可是不同决定；如需允许他人按特定条款复用，可之后单独添加许可证，第三方许可仍分别适用。
